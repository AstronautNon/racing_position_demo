### 三个方法论决定（重要，后续别退回）

2. **相机静止性判据**从帧间配准改为**直接检验背景模型**：中值背景扣掉最大连通域后的

   实测画面里存在 309×23、平均差异 117 的**字幕带**，纯按面积会被它抢走。

## L4 标注链路（选帧 + 标注台）

新增 `src/crops.py`、`src/select_frames.py`、`src/annotate.py`。

### 选帧：贪心最远点采样
特征 = 朝向代理 [cos2θ, sin2θ] (w=1.0) + 画面位置 (0.7) + 时间 (0.8) + 外观 48×48 灰度 (0.6)。
距离 = 几何项欧氏距离 + 0.6×(1−|余弦相似|)。起点取置信度最高帧，逐轮选"与已选集最小距离"最大者。
配额 `ANNOT_QUOTA` 合计 230 帧（video12:55 / 02:50 / 03:45 / 15:35 / 01:25 / 09:20）。

### **用实测推翻的一条判据：贴边不能按"距边缘留白"判**
第一版 `ANNOT_EDGE_MARGIN=0.01`（框距边 <1% 即剔除）→ video15 只剩 **7 个候选**、video12 只剩 96 个。
根因：检测框被**车身阴影**撑大（video15 框宽 / 车身核心宽 = 1.18，p90 2.07），
"贴边"多为阴影尾巴越界，车本身在画面内。
改为按**越界幅度 / 框长边 ≤ 0.10** 判：video15 7→42、video12 96→186、video03 123→192。
依据：最多 10% 车身长度在画面外，剩余 90% 仍足以定出车身轴。
（曾试过用"强差异核心"分离车身与阴影，但 video12 地面轮胎痕差异更强，核心框反而比检测框大，
 该指标不可用 —— 记录备查。）

### 标注台设计
- **只点两个点**：车身轴无向，180° 歧义由 `undirected_resolve` 用运动方向消解。
- 角度**必须换算回工作图坐标**再算：裁图两方向缩放比不严格相等（贴边时裁图被夹成非方形）。
- 两种模式：`--serve`（本地服务，POST 直接落盘）/ `--export`（自包含 HTML，base64 内嵌图片 + localStorage）。
- 标注 CSV 存 `k,axis_deg,x1,y1,x2,y2,src,ts`；xz 后几列是**工作图坐标**下的原始点选，供复核。
  `src=manual` / `src=hint` 区分人工点选与"采用 PCA 提示"。
- 贴边帧给侧栏警示（`cut` 标记），标不准按 `N` 跳过。

### 验证方式（本机没有 agent-browser，用 Chrome headless）
`"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --dump-dom` +
注入 harness 模拟 PointerEvent。**注意 `--virtual-time-budget` 与页面定时器会互相作用，
Chrome dump 完不退出**——正确姿势是后台启动、`sleep` 后 `kill`，再解析已落盘的 DOM。
测过并通过：单击角度误差 0.010°、拖动角 26.6°（理论值）、T 键 src=hint、U 撤销回退、
CSV 列齐、覆盖物无越界、0 JS 异常。

### 修掉的三个前端缺陷
1. `setPointerCapture` 在合成事件/部分 webview 会抛 NotFoundError → 包 try/catch。
2. 独立模式保存时丢掉 `ts` → 导出的 CSV 缺时间戳。
3. **独立模式忽略导出时嵌入的既有标注**（只读 localStorage）→ 重新导出的页面看不见之前标的帧，
   还会把它们当"未标注"覆盖掉。改为：先铺载荷里的既有标注，再用 localStorage 覆盖同 k 项。
4. 撤销后没回写 localStorage → 删掉的标注重开页面会"复活"。
