## 素材获取工具链体检（为本项目补充素材做准备）

实测本机环境：

- **yt-dlp 已装**：`/Library/Frameworks/Python.framework/Versions/3.13/bin/yt-dlp`，版本 2026.03.17。
- **ffmpeg / ffprobe 全机缺失**：`/usr/local/bin`、`/opt/homebrew/bin`、各 conda env（含 racing-pose）均无。opencv 自带的 ffmpeg 库只够 `cv2.VideoCapture` 读视频，不能供 yt-dlp 合并音视频流。
  - 影响：`yt-dlp` 默认格式合并、`-x` 抽音轨、容器转换都会失败，必须补 ffmpeg 或改用 `-f` 选单一已封装流。
- **无 Homebrew**，装 ffmpeg 的轻量路径是 `pip install imageio-ffmpeg`（自带静态二进制），再 `yt-dlp --ffmpeg-location <exe>`。

## 素材采集原则（已确认）

1. 优先取**原始文件**，禁止录屏——录屏是当前 50%~72% 重复帧的根因。
2. 免费素材站（Pexels / Pixabay / Coverr 等）多支持直下 mp4，无插件、无二次编码。
3. 网页播放器流用浏览器扩展嗅探，命令行兜底用 yt-dlp。
4. 下载后建议串一遍重复帧检测 + 帧率/分辨率检查，把素材体检前置。

## 素材库扩容至 15 段（video07~15 新增 9 段）

### 判据修正（重要，后续统一口径）
- 旧的重复帧判据（240×160 灰度平均绝对差 < 0.5）在**小目标 / 慢运动**画面上会严重高估重复率：video07 被判 95.2% 重复，实为 9.5%。
- 统一改用**变更像素占比判据**：480×270 灰度下 `|diff| > 20` 的像素占比 < 0.05% 判为重复帧。
- 该判据复现了旧素材 video01/02/03 的重复率（71.5% / 60.8% / 50.3%），旧结论无需推翻；但 video04/05/06 差异大（13.3% / 50.9% / 29.2%）。
- 相机静止性判据：相位相关法测相对首帧的累计平移，位移 < 1% 画面宽视为静止。

### 新素材结论
- **重复帧率 3.5%~31%，比旧素材的 50%~72% 好一个量级**（video13 例外 42.6%）。
- 静止机位（可用背景建模）：video07/08/09/12/13/14/15；**相机在动**：video10/11（位移 14.6% / 12.8%）。
- 可用裁图（视觉互不重复 @0.95）从约 250 张升到 **495 张**。
- 独立来源从 3 个升到 **8~9 个**，可做真正的多源 train/val/test 划分。02 与 03 同场地的限制仍在。
- 出现真正的正俯视素材：**video12**（碎石定圆，11.6s，车 378×256）、**video15**（车 491×315，但是录屏，有黑边+水印+片头）、video13/14（**八字**动作，但仅 640×360）。
- 主线调整：video12 + video15 + video02 + video03；video13/14 待回源找 1080p；video10/11 归难例。
