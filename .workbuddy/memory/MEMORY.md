# 漂移评分系统 · 项目长期记忆

> 详细规则见 `README.md`（十四个关键约定）与 `项目规划.md` §14。这里只放最容易踩的几条。

## 数据来源的可靠性分级

- **车身朝向 ψ_body 唯一可靠来源 = 人工标注**（`outputs/annotations/*.csv`）。
  掩膜 PCA 主轴只能当**粗初值**：掩膜实际是"运动月牙"而非车身轮廓，
  会把地面暗带/车身投影吃进去，实测 video15 上被**系统性带偏约 30°**（且随姿态变化）。
- **车头朝向是"推出来的"，不是观测来的**（`undirected_resolve` 取与运动方向夹角 ≤90° 的一端），
  故 β 被结构性夹在 (−90, 90]；真·|β|≥90 时车头判反而曲线看不出异常。

## β 的两半要分别体检（β = ψ_body − ψ_vel）

两个真案例，各坏一半：

- **ψ_body 那一半**：轴是人工点的，靠 `tools/qa_pose.py` 的帧间物理界抓点选错误。
- **ψ_vel 那一半**：速度是位置导数，**位置坏了方向就坏**。两类位置失效：
  - **水雾/阴影尾迹并进掩膜 → 质心被平滑地拖偏**（video15 开头 k=1~14 偏 11~90 px）。
    注意：**位置序列平滑 ≠ 位置正确**，所以任何"位置跳变"式判据（含
    `reject_pose_outliers`）**原理上发现不了它**。用 `tools/show_trajectory.py` 看形状。
  - **位移与检测噪声同量级 → 方向就是噪声**（video12：σ_pos 2.79 px vs 位移 3.27 px，
    38/55 个标注帧不可信）。判据是自适应的 `SNR = speed·dt / σ_pos`，
    在 `src/qa_pose.py::psi_vel_quality()`，报告 §4 有「运动方向可信」列。

## 判据之前先问前提

- **时间基准**：素材是不是实时，登记在 `src/config.py` 的 `VideoSpec.realtime`。
  `False`（如 video15，原片加速过）时，`°/帧`、`°/s`、`px/s`、`t` 全是**名义值**，
  不准用来推断"数据有错"。加速倍率未知就不要臆造换算系数。
  **但角度类量与 SNR 不受影响**（方向与时间基准无关；SNR 的 dt 在分子分母上约掉了）。
- **别用一个原因解释两件相邻的事。** 曾把"帧间速率异常"和"位置离群"都归给"加速"，
  实际两者机制完全不同。归因要各自查实。
- 素材的一切元数据（机位、检测器、裁切、mask 带、realtime）**一律登记在 `config.py`**，
  不要散落到各处代码里。

## 容易写错的度量

- 量"两条无向轴的差"必须用 `kinematics.axis_dist`（折 90°）；
  用 `angle_diff`（折 180°）会把 0° vs 179°（其实差 1°）报成 179°。
- 标注一致性报告要**中位与 p90 并列**，只报中位数会把 80.78° 的 p90 藏住。
- **忘了传 `body_axis` 就去看 `kin["beta"]`，得到的是 PCA 基线值**，不是交付值。
  本轮因此误读了一次（把 PCA 基线当成 "β 跨 ±90 边界"）。用 `tracks/*.csv` 里的值最稳。

## 标注队列的操作红线

- 已全部标注的队列**冻结**；未完成的与旧队列**取并集**。
  不要为了"让队列更整齐"重生成 —— 实测会把已标帧挤出队列，让人白标一遍
  （标注数据不丢，但队列不再对应人工作品）。生成器已加保护（`--rewrite` 可强制）。

## 当前交付范围与已知缺陷

- **只做姿态**：车头朝向 ψ_body、运动方向 ψ_vel、两者之差 β。
- 比例尺标定与物理单位换算（px/s → m/s）**已明确延后**，不属本阶段。
- **当前唯一交付级缺陷：video12 的运动方向不可信**（38/55 标注帧 SNR<3），
  需决定：放宽定位后重算 / 降级为只看趋势 / 换源片。
- video15 开头 k=1~14 的质心污染只作诊断记录（影响 β 约 8°，其中标注帧仅 k=14）。
